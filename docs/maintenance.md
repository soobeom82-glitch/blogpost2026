# 유지보수 및 인수인계 — 2026-11-18

기준 원격 커밋은 `291ba6c`이며 작업 브랜치는 `codex/stabilize-blog`입니다. 수정 사항은 이 작업 브랜치에서 관리하며, 아래 검증 결과는 로컬 환경 기준입니다. 운영 배포 및 외부 환경변수 확인은 별도입니다.

## 수정한 문제

- 일일 리포트 인증을 추가하고 미리보기를 실제 발송과 분리했습니다.
- 좋아요·조회수에 서명된 익명 브라우저 식별값과 DB 중복 방지를 적용했습니다.
- 글 존재 여부, 댓글 타입·길이·답글 대상·깊이를 검증하고 요청 횟수를 제한합니다.
- 좋아요 재방문 시 +1 표시와 실패를 성공처럼 유지하던 동작을 제거했습니다.
- PostgreSQL 통계와 이벤트 기록을 트랜잭션으로 묶고 동시 작업을 직렬화합니다.
- 로컬 JSON에 프로세스 간 파일 잠금과 원자적 교체를 적용했습니다.
- 기존 댓글 비밀번호 검증을 유지하면서 scrypt 저장으로 전환합니다.
- DB 장애가 본문까지 막지 않도록 처리하고 댓글·통계 오류를 화면에 표시합니다.
- 공매 가이드 순서를 명시적 메타데이터로 관리하고 운영노트 주제 필터를 통일했습니다.
- 독립 글을 임의의 연재로 취급하지 않습니다.
- 글 목록 자동 생성, 메타데이터·이미지·글 링크 검사, CI를 추가했습니다.
- 하위 페이지 canonical, JSON-LD 이스케이프, 공유 실패 안내, 폼 접근성을 보강했습니다.
- Next.js 16.4.6, React 19.3.1 및 관련 의존성을 고정하고 제거된 next lint를 Biome으로 교체했습니다.
- README, 배포 문서, 환경변수 예제, AGENTS.md, 백로그 상태를 갱신했습니다.

글 본문은 바꾸지 않았으며, 연재 글의 분류·순서 메타데이터만 추가했습니다. 기존 누적 통계와 댓글을 초기화하지 않습니다.

로컬 검사 실행 Node는 26.3.0입니다. `.nvmrc`와 CI는 Node 22를 사용하며, 연결된 Vercel 프로젝트 설정은 Node 24.x로 확인했습니다. CI 실행 결과나 실제 운영 배포의 성공 여부까지 확인한 것은 아닙니다.

브라우저 테스트는 로컬 서버와 임시 데이터를 사용하며 실제 Telegram 메시지를 보내지 않았습니다. 자동화 검사에서 처음 발견한 정상 요청의 Origin/내부 호스트 불일치도 수정 후 재검증했습니다.

## 배포 전에 남은 외부 설정

- 운영 DB 연결과 `ENGAGEMENT_SECRET`(최소 32자)을 확인합니다.
- 일일 리포트를 사용하려면 `CRON_SECRET`, Telegram 토큰·채널을 확인합니다.
- 문의 이메일, 실제 사이트 URL, Search Console와 AdSense 설정은 운영자가 사용하는 값과 맞는지 확인합니다.
- Vercel 프로젝트 정보는 읽을 수 있었지만 환경변수 목록은 API가 403으로 거부했습니다. 변수의 존재·값은 확인하지 못했습니다. 로컬 Vercel CLI도 설치돼 있지 않았습니다.
- 계정의 환경변수를 읽거나 바꾸지 않았으며, 배포도 실행하지 않았습니다.

익명 쿠키는 사람의 신원을 증명하지 않습니다. 쿠키 삭제나 브라우저 변경 후에는 새 식별값을 받습니다. 과거 좋아요는 사용자 매핑이 없어 보존된 누적 숫자로 남습니다. 리포트는 외부 발송 직후 장애가 발생하면 재시도 과정에서 중복될 수 있습니다. 세부 기준은 DEPLOY.md에 있습니다.
